### 记忆系统

记忆系统由实体，实体结构化信息，语义信息构成，实体和实体通过结构化信息关联，实体和语义信息也可关联。

#### 实体

是指在信息中具有明确或可区分身份的现实对象。它可以被唯一或相对稳定地识别，具有一组属性，并能够与其他实体建立关系。

比如：

- 公司：OpenAI、Google、字节跳动
- 一个人：张三、李四、马斯克
- 组织：研发团队、学校、政府机构
- 地点：北京、东京、某个办公楼
- 产品：iPhone、ChatGPT、MacBook
- 项目：某个软件开发项目
- 作品：一本书、一部电影、一首歌曲
- 技术：Python、RAG、Transformer

核心判断标准： 一个对象是否具有相对独立的身份，能否被单独指代、识别，并在不同上下文中保持身份连续性。

例如，「公司」是实体类型，而「OpenAI」是一个具体实体；「人」是实体类型，而「张三」是一个具体实体。

#### 实体结构化信息

实体结构化信息表示实体当前所处的状态。

初始化实体结构化数据如下：
```json
{
  "id": "uuid",
  "keywords": "",
  "relations": {}
}
```

字段说明：

所有字段都是 key=value，value 都为 string。

- id：必要，初始化自动生成，是 uuid。
- keywords：必要，暂无关键词，可为空字符串，多个关键词用逗号分隔。
- relations：必要，暂无关系指向，可为空对象结构。

relations 具体说明：

表示和其他实体的关系，某个关系有多个实体，用逗号隔开，比如：

- 朋友：```"relations":{"friends":"uuid-1,uuid-2"}```
- 同事：```"relations":{"friends":"uuid-3"}```

实体结构化信息存位置：

.memory，比如：实体 id=uuid -> .memory/uuid-1.json。

#### 语义信息

和实体有关的事实，偏好，目标等内容，或者是明确需要记住的信息。

比如：

1. user：我在巨核科技工作。 -> `我在巨核科技工作。`
2. user: 记住 1+1=3 -> `1+1=3`

语义信息存储位置：

.memory/memory.db


#### 记忆的提取与存储

在给定的信息中，识别到实体，实体关系，实体关系变更或者明确要求记忆某个信息时，需要创建和更新记忆内容。

比如：

user: 我的同事是黄志鑫，我在巨核科技工作。

提取：

- 实体：「我」「黄志鑫」「巨核科技」
- 关系：「同事」「员工」「公司」

生成实体结构化信息并保存：

```json
{
  "id": "uuid-1",
  "keywords": "我",
  "relations": {
    "colleagues": "uuid-2",
    "companies": "uuid-3"
  }
}
{
  "id": "uuid-2",
  "keywords": "黄志鑫",
  "relations": {
    "colleagues": "uuid-1",
    "companies": "uuid-3"
  },
  "name": "黄志鑫"
}
{
  "id": "uuid-3",
  "keywords": "巨核科技",
  "relations": {
    "employees": "uuid-1,uuid-2"
  },
  "name": "巨核科技"
}
```

创建语义信息并进行向量化保存：

我的同事是黄志鑫，我在巨核科技工作。-> 向量化 -> metadata

user: 我叫谢佳鹏，我离职了。

提取：

- 实体：「我」「谢佳鹏」

思考逻辑：

1. 「我」匹配到 uuid-1 实体
2. 更新
