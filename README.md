# 本地记忆系统

从当前会话中提取有充分证据的实体、当前属性和关系，将语义信息追加保存到本地 Milvus。主 Agent 使用当前聊天上下文回答；本版不检索持久记忆辅助回答，也不持久化聊天记录。

需要 Python 3.13+、`uv`，以及系统环境变量 `DEEPSEEK_API_KEY` 和 `DASHSCOPE_API_KEY`。直接读取环境变量，不需要 `.env`。

```sh
uv sync --locked
uv run memory
```

输入 `/exit`、`/quit` 或按 Ctrl-D 退出。空白输入会被忽略，Ctrl-C 会结束会话并关闭资源。

模型固定为 `deepseek-flash`（主 Agent 和记忆 Agent）和 `qwen3.7-text-embedding`（向量化）。DeepSeek SDK 还支持已有的 `DEEPSEEK_API_BASE` 环境变量；不会在模型失败时自动切换模型。输入超出服务限制时会报告失败，不自动截断或摘要历史。

数据位于启动命令所在目录下的 `.memory/`：

- `agent.json`：首次启动生成的内置 Agent；重复启动保留内容。
- `<uuid>.json`：实体当前属性与关系，采用局部更新。
- `memory.db`：由 Milvus Lite 管理的本地数据库路径，语义记录只追加。首次有效语义向量决定集合维度，无需保存语义时不调用模型探测维度。

例如，`记住 1+1=3` 会按原文保存无实体语义；`他可能离职了` 不会据此解除任职关系。同名或指代不明的内容会被舍弃，独立且明确的内容仍可保存。未知的“我”不会创建匿名用户实体；新会话不自动继承上次对话中的用户身份。

终端会显示记忆处理的实际状态：已完成、未写入、部分完成或失败。多实体文件与数据库之间没有全局事务；失败时保留已确认写入的数据。写入结果未知时不自动重试，重新请求保存可能产生重复记录。

现有 JSON 损坏、悬空引用或数据库结构不兼容会明确报错并保留数据，不会自动迁移、清空或重建。当前锁定的 Milvus Lite 3.2.2 在 gRPC 创建数组字段时会丢失元素长度参数，因此首次建库使用该依赖的公开原生建表接口保留参数，后续读写继续使用 PyMilvus；存储后端和四字段结构不变。

实现依据及验收记录见 [Spec](specs/spec_1_0.md) 和 [Plan](plans/plan_1_0.md)。项目目前没有测试、Lint 或类型检查配置；本次使用隔离临时目录中的直接调用、故障注入和真实模型联调验证，未新增测试文件。
